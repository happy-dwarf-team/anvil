Address declarations, prototype

Throwaway prototype for the Anvil 2 ticket "One source of truth for game addresses". Not production code.

Question. How should a plugin declare the game addresses it uses once, so that the plugin's code and Anvil's verification come from the same declaration?

The sample plugin is a menu-return port: two hook sites and a function-pointer slot taken from EU4 Menu Patch, and a game-speed read plus a function call taken from Tongs (real RVAs and bytes of EU4 1.37.5). Pick a declaration style, change the game or the plugin with the buttons, and watch what Anvil checks before it loads the plugin and what the plugin's code actually uses.

Styles: Aa symbols file and a generator, Bdeclarations in the plugin's own source, read by Anvil from the DLL file, Clike A, but common game symbols come from a shared address library, API 1today: addresses in code and [[expect]] in the manifest.
