# The Manager reads the plugin catalog at start when the player agreed to the release check

More players use Anvil and its plugins, and the team releases plugins more often than Anvil. A player learns that an installed plugin has a newer pinned release only by opening the Catalog tab and clicking **Get the current list** ([ADR 0002](0002-manager-plugin-catalog.md)); until then the tab compares the installed plugins with the list built into the Manager, which is as old as the Manager. Most players never click it, so fixes reach them late or never. This changes the consent bullet of ADR 0002 ("the list is not fetched at start, not even when the release check is on"): the rest of ADR 0002 stands.

- **What goes to the network.** One HTTPS GET of `raw.githubusercontent.com/happy-dwarf-team/anvil/main/catalog/plugins.json` per start of the Manager, sent as `AnvilManager/<version>`, at most 256 KiB, validated as ADR 0002 says. It is the request **Get the current list** sends, made for the player. Nothing else changes: no zip is downloaded, no plugin is installed or updated without the player's **Update**, the confirmation that names the file, its size and its host, and the zip dialog.
- **Consent.** The same answer as the release check (`check_releases` in `%LOCALAPPDATA%\Anvil\manager.toml`, or, when the Manager never asked, the overlay's `release_check` set to `on` or `off`; [ADR 0005](0005-release-check-in-the-game.md)). There is no second question. The question and the About checkbox say so: "new releases of Anvil and of the team's plugins", and the Catalog tab says the list came with the release check and where to turn it off. With the check off, the Manager reads nothing at start, as today, and **Get the current list** still works on a click.
- **When and how often.** Once per start of the Manager, on a worker thread, next to the release check; again when the player turns the check on (the question's Yes or the About checkbox), as the release check does. Not per game folder (the list is the same for every folder), not on a timer, and not while the Manager stays open. The overlay does not read the catalog (see the options below).
- **Without the network.** The GET fails or the list does not validate: the Manager keeps the list it has (its own, or one fetched earlier in this start) and the Catalog tab names the error in one line, as after a failed click. Nothing is retried; **Get the current list** asks again.
- **What GitHub sees.** The player's IP address, the time, and that it is a Manager of that version, a second request to GitHub next to the release check's. Nothing about the game folder or the installed plugins: the list is the same file for everyone, and the comparison with `anvil/plugins` is made in the Manager. `raw.githubusercontent.com` is served by GitHub through a CDN, which caches the file for a few minutes; a merged pin may therefore reach a Manager a few minutes late.
- **What the Manager shows.** A plugin in `anvil/plugins` whose pinned version is newer than the installed one, for this game build and the installed Anvil, is an update. Updates come from the list the Manager has: its own until a fetch succeeds, so with the check off or without the network the built-in list can still show one, as the Catalog tab's **Update** button already did; no request is needed for that.
  - the Catalog tab's label carries their number, `Catalog (2)`, and the entry says "Version 0.19.0 is installed; 0.20.0 is available." next to its **Update** button;
  - the Plugins tab's row says "0.20.0 is available in the Catalog tab", with a button that opens that tab.
  - A pin that the installed Anvil or the game build cannot run is not counted: the Catalog entry shows why, as it does today. A newer installed version (a build of the plugin's `main`) is not an update.
  - Nothing is downloaded or installed by itself: **Update** is the existing install path, with both confirmations.
- **Plugins from Workshop mods.** A plugin that comes with an enabled mod updates through Steam, which updates the mod; Anvil then keeps loading the approved version until the player approves the new files, in the overlay or on the Mods tab (design §14). The catalog check does not count those plugins, so a player is never told to install a copy in `anvil/plugins` that would shadow the mod's. A plugin in both places counts only through its copy in `anvil/plugins`, which is the one that loads.

## Considered options

- *A separate question for plugin updates.* Rejected, but it is the alternative the maintainer may prefer. It keeps the release check's consent to what its first wording said (one link for Anvil), at the cost of a second question and a second setting for a request to the same company at the same moment that tells it nothing more. ADR 0005 rejected two settings that mean almost the same for the same reason. A player who said yes in an older Manager said it for Anvil's releases only; the Manager that brings this check rewords the question and names the plugin list in its Catalog tab, and the About checkbox turns both off.
- *Fetch the list at start without asking.* Rejected: it is a request to GitHub that the player did not agree to, and design §19 promises that nothing happens on the network by itself.
- *Read the list in the game, through the overlay.* Not now: the notice would have to say "open the Manager and update there", the overlay would need the catalog's parser and the plugins' versions, and the game starts far more often than plugins are released. The overlay's release check may later name plugin updates once this one has been used.
- *Install updates automatically.* Rejected: a plugin is native code, and the player confirms the file and the zip dialog before it lands (ADR 0002). An update can also change the game (`affects_gameplay`) and needs the player's eye.
- *Keep the fetched list on disk and read it at the next start without the network.* Not done: a list from the last start is older than a fresh one and newer than the built-in copy only for a while, and a file in `%LOCALAPPDATA%` that changes what the Manager offers is one more thing to validate. The built-in list stays the offline answer.
- *Ask GitHub's API for each plugin's latest release.* Rejected for the reasons of ADR 0002: the pin, not the latest release, is what CI verified, and one request per plugin would grow with the catalog.

## Consequences

- Design §15 and §19 say the Manager reads the catalog at start when the release check is on; README, the website's install and safety pages and the Workshop texts that say "nothing is downloaded until you click" are reworded where they speak of the list.
- Players who agreed to the release check see plugin updates the first time they open a Manager that brings this change, a few minutes after the pin is merged.
- A pin merged on `main` reaches those Managers at their next start, before the next Anvil release; the pin's review in its pull request carries more weight than before.
- The Manager's question, About checkbox and Catalog tab gain texts in all seven catalogs, machine-drafted until a native speaker checks them.
